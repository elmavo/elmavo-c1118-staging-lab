# ELMAVO Synthetic Diagnostic Lab

Inactive preparation only. No product source, customer data, credentials or real target identifiers.

GitHub Actions must remain disabled. The manual example uses standard ubuntu-24.04, read-only repository permission, an environment and an OFF-by-default gate. No cron, PR trigger, dispatch, secret, deployment or measurement is configured here.

Run locally with Node >=22.18: node prepare.mjs

The Cloudflare collector and Workflow/SQLite DO safety core reuse the reviewed diagnostic protocol. Examples use fixture identifiers and staging.invalid, with routes, previews and ENTRY_ENABLED disabled. They cannot measure the retained staging target. No D1 binding or schema is included.

Limits: 200 controlled requests, at most 4 logical concurrent operations, at most 10 minutes. Data stops at minute 7, Cloudflare closure at minute 8, GitHub closure at 8:30, verification at 9:20. Durable intent/receipt precedes I/O. Unknown result never implies success or an automatic retry.

Closure requires management OFF plus anonymous HTTPS 404. Provider failure or missing evidence means BLOCKED. Region hints and two processes do not prove two D1 regions.

Live credentials, trusted readiness, persistent GitHub journal, private collector trigger and real cloud failover verification are not connected. No public route or access window may be enabled without separate approval. These files are preparation artifacts, not proof of regional consistency or production readiness.
